## Why

A reference video shows the live code drawn right on top of the visual: one band per line as wide as the text, the visual breathing through the empty lines, the line being typed in its own colour, the playing notes outlined, and two small widgets drawn inside the code (a drum step grid and an ASCII chromagram with the chord name). The owner likes it: "very cool, gives a lot of flexibility, showing the code right on the visual; and gave us the idea of custom widgets". Today our code always sits in its own panel (the editor column in the page, a separate area in videos and fragments), and the only widgets in the code are Strudel's (`#79`).

## What Changes

- **"Code over" layout** (it: "Codice sopra") for the stage and for videos: the code drawn transparent over the scene, in 16:9 (session video, live output, the page's stage) and in 9:16 (fragments). One band per line, as wide as the text; empty lines without a band; comments and muted lines dimmed; long lines cut with `…` in this layout only (the editor and the other layouts keep the whole line). Band colour and opacity come from the code theme, with Neon, Hardware (amber) and Light variants, readable over every look and render style. The render style never touches the code (as today).
- **The page:** a stage mode "Code over" (a button in the stage bar and in full screen). The stage grows, the editor column folds, the code is drawn on the stage. Taking over by hand opens the editor again.
- **Captions and stage widgets in this layout:** in 16:9 the caption lane moves to the visual's side of the frame; in 9:16 it sits under the code area. The stage widget strip keeps only the side away from the code (16:9) and is off in 9:16; the full looks (Monitor, Rullo, Claude, Soul) stay available under the code.
- **Line being edited:** while the coder types a line, the line's band takes the theme's edit colour with a block cursor; it goes back to normal when the edit ends. Same in real time and in the fast video, from the typing plan.
- **Lit notes outlined or filled:** a code theme option "Lit notes" (it: "Note accese"): Outline (default, as Strudel draws them in the editor) or Filled. In videos and in "Code over" the lit notes follow the real hap locations instead of today's approximate box.
- **Custom code widgets:** a small app widget kind next to Strudel's, written in the code like the `#79` widgets (`._rhythm()`, `._chroma()`), with parameters in the call and defaults from Settings; drawn from the code's haps (exact, deterministic, works in the fast video), never from audio; one painter used by the editor, the "Code over" layout, every video and the live output.
  - **Rhythm grid** (it: "Griglia ritmo"): one row per drum sound, 16 steps per bar in 4 beats, the current step column, played and coming hits, `battuta 13 · passo 16/16` (`bar 13 · step 16/16`).
  - **ASCII chroma** (it: "Croma ASCII"): 12 note rows over time, intensity as a character ramp (` .:-=+*#%@`), the current chord's notes with inverted labels, the chord name below.
  - **Parameters** with defaults: steps per bar, bars shown, rows shown and their order, short or long names, extra melodic rows, style (blocks or characters), trail, size; for the chroma, source instruments, columns, bars shown, ramp, row order, normalisation, decay, labels, chord name, size. Colours always from the code theme.
  - **Every render style:** blocks in Normal, CRT, LED (round cells) and 1-bit (two tones); characters in ASCII and Terminal.
  - The two widgets join the "Code widgets" option (`#79`): the rhythm grid is the drums' primary widget, the chroma the pad's (chords'); they count toward the maximum.
- **Labeled lines** (it: "Righe con nome"), a code-look option: `kick: s(...)`, `bass: note(...)` instead of a comment naming the instrument followed by `$:`. Names are lowercase, unique, generated by us (`kick`, `kick2`); mute is `_kick:`, solo `Skick:`. A guard warns on user code when two lines share a name (only the last plays), when a name starts with a capital `S` (it solos the line) or ends with `_` (it mutes it). Off by default; the sound never changes.
- **Test video and mockups** of the layout, the edited line, the outlined notes, both widgets with parameter variants, the settings and the label notation, made with a throwaway prototype in `prototype/`.

Out of scope: widgets fed from audio analysis; turning an audio file into code; a staged syntax error, a moving `slider(…)` value and edits landing on the bar (a later "live typing" change); new stage looks.

## Capabilities

### New Capabilities

- `code-over-visual`: the "Code over" layout in the page's stage, videos, fragments and live output; bands, truncation, the edited line, lit notes outline or fill, captions and stage widgets in this layout.
- `custom-code-widgets`: app widgets written in the code and drawn from haps, with the rhythm grid and the ASCII chroma, their parameters, settings and render style forms.
- `labeled-lines`: the labeled line notation option, its naming rules, mute and solo, and the guard on user code.

### Modified Capabilities

None in `openspec/specs/`. The open changes `code-widgets`, `code-themes`, `widgets-on-stage`, `widget-render-styles`, `spoken-text-on-stage`, `fast-video` and `live-typing` are read by this change: it adds two widget kinds to the first, an option to the second, and new layouts next to the others.
