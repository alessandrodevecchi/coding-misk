## Context

- "Lit notes" lives in the code theme settings (`src/code-themes/themes.js`, `CT_DEFAULTS.lit`, values `outline` and `fill`). The editor draws Strudel's own highlight marks, which carry an inline `outline: solid 2px …`; Filled is a CSS rule in `src/code-themes/install.js` that drops the frame and fills the token. "Code over" and the video code layouts draw their own marks in `src/video/code-over.js` (`T.lit === 'fill'` fills, otherwise strokes a frame) from the `litForm` passed by `src/video/video.js`.
- The code theme roles already have an accent: `R.widget.a1`, else `R.caret` (used for the edited line in "Code over", `overRoles`).
- "Widget notes" is `CW_DEFAULTS.notes = 'volume'` in `src/live/widgets.js`. Code widget settings are stored whole (`setCw` writes every field with the defaults filled in), so a stored `volume` does not tell whether the user chose it.
- Settings rows are built by `row(label, control, hint)` in `src/settings/settings.js`: the hint is a visible line under the control; there are no tooltips on labels today. Of about 110 rows, 47 have no hint.
- The stage widgets card uses `swLayer:palco` = "Palco" in English, and `swLayerHint`, `swStripHint`, `swColoursHint` say "Palco". The visual's English name is "Stage" (`src/music.js`, `LOOKS`).
- `outKindTip` (the audio/video switch of the radio export, `src/main.js`) ends with "Video runs in real time"; the fast video renders faster than real time since `fast-video`.

## Goals / Non-Goals

**Goals:** a third lit form; the new default for "Widget notes" reaching existing users too; a help text for every Settings control in both languages; the two label fixes.

**Non-Goals:** new names for the "Over the scene" modes (change `stage-app-widgets`); help texts outside Settings; changing what any control does.

## Decisions

### D1. Underlined: a 2 px line in the accent colour

The underline sits under the token's glyphs (at the text's baseline plus a small gap), as wide as the token, `max(2, fontSize / 12)` px thick, in the accent colour `R.widget.a1 || R.caret`. In the editor it is a CSS rule like Filled's: the inline outline removed, `box-shadow: inset 0 -2px 0 <accent>` (a box shadow does not move the text or the line height, unlike `border-bottom` or `text-decoration` on Strudel's marks, which CodeMirror may merge). In "Code over" and videos the painter draws a filled rectangle under the token. On the edited line in "Code over" the underline uses the edited line's ink, as Outline and Filled do.

| Option                                                                        | Notes                                                                                                                 |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **A (chosen)** `box-shadow: inset` in the editor, a rectangle in the painters | No layout shift; same look in both places                                                                             |
| B `text-decoration: underline`                                                | Its colour and thickness depend on the font; CodeMirror splits marks across tokens, so the line breaks at token edges |
| C `border-bottom`                                                             | Changes the line height in the editor: the code jumps while notes light                                               |

**Contrast fallback:** when the accent has less than 3:1 contrast against the panel's background (or against the band in "Code over"), the text colour is used. `check:code-themes` gains the underline role and lists the fallbacks.

### D2. Widget notes: a one-time move to the new default

`CW_DEFAULTS.notes` becomes `full`. Stored settings carry a version field `v`; settings without `v` (written before this change) with `notes: 'volume'` become `full` once, and `v: 2` is written. A user who picks "Follow the volume" afterwards keeps it.

| Option                                            | Notes                                                                                                  |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **A (chosen)** one-time move with a version field | The owner and every tester see the new default without a reset; later choices are kept                 |
| B only the new default                            | Anyone who ever changed a code widget setting keeps the old default, because settings are stored whole |
| C reset the whole code widgets card               | Loses other choices                                                                                    |

The stage panels with "Same as code widgets" read `notes` from the code widgets, so they follow. A stage mapping "Own" has no notes field of its own (it uses the code widgets' one): nothing to move there.

### D3. Help texts: the hint line stays, the label gets a tooltip

Each `row()` gets its help text both as the visible hint line (as today) and as `title` on the label. Touch devices see the hint line; a pointer sees the tooltip without reading the whole card. Rows whose hint changes with the value (layout, soul, phrases) keep that; their tooltip is a general sentence about the control.

| Option                                      | Notes                                                                         |
| ------------------------------------------- | ----------------------------------------------------------------------------- |
| **A (chosen)** hint line plus label tooltip | No new UI; the hints already exist; the check can count them                  |
| B an info icon with a popover               | One more control per row, hidden text on touch, more work for keyboard access |
| C tooltips only, hint lines removed         | Shorter cards, but touch users lose the help                                  |

**The check:** `check-settings.cjs` lists every `.set-row` and fails when a row has no hint and no title, or when a key is missing in one language. Help texts follow the knowledge base style: plain, at most two short sentences, the default named when it matters.

## Risks / Trade-offs

- **Long tables drift:** the texts here are proposals; the implementer may adjust wording to the code's real behaviour and notes the differences in the DEVLOG. The check guards only presence, not quality.
- **Underline on Strudel's themes:** some installed Strudel themes have a weak accent; the 3:1 fallback keeps the underline visible but in the text colour, so it may look less special there.
- **One-time move:** a user who had chosen "Follow the volume" on purpose before this change loses that choice once. Acceptable: the option was added recently and the owner asked for the new default.

## Open Questions

1. Should Underlined become the default instead of Outline? Recommended: no, keep Outline as the default (Strudel's own look), and let the owner try Underlined first.
2. Should the tooltip of a row also show on its control (the select or the buttons), not only on the label? Recommended: label only; the controls already carry their own values and some have their own titles.
